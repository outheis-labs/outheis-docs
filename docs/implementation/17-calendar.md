
# Calendar

*The visual schedule view in the outheis WebUI.*

---

The calendar is the `agenda` tab in the WebUI. It renders your schedule as an interactive timeline — time-boxed events as blocks, floating tasks as freely positionable labels, and a continuous colored background that reflects the weight of what's planned.

The calendar reads from and writes to `agenda.json`:

```
~/.outheis/human/webui/pages/agenda.json
```

This file is generated by cato on each hourly run and can also be saved directly by the calendar UI. For the data format, see [agenda.json Reference](16-agenda-json.html).

---

## Item types

### Fixed events

A fixed event occupies a defined time slot on the timeline. It renders as a block spanning the exact start–end interval.

- Drag horizontally to reschedule (within the same day or cross-day)
- Resize with the left or right handle at the block edges
- Double-click to open the edit popup

**Multi-day events** (ISO datetime format) span multiple day strips with a connected bar. The first strip shows title and dates; subsequent strips show the continuation.

### Volatile items

A volatile item has a day but no fixed time. It floats freely within its day strip as a label.

- Drag in 2D: reposition within a day, or drag vertically to a different day
- Double-click to open the edit popup
- Items with a **duration** (`#time-HH:MM`) render as a bounded box with dashed border, sized proportionally to the duration

Volatile items with no stored drag position are distributed automatically across three Y bands within the day strip, using a deterministic hash of title + day so the layout is stable across reloads.

### Recurring items

Recurring events are stored as a single anchor item in `agenda.json` carrying a `#recurring-*` tag. The calendar generates display instances for all visible days that match the recurrence pattern — these are never written back as individual items.

See the [agenda.json Reference](16-agenda-json.html#recurring) for supported recurrence tags.

## Visual model

### Gravitational field

Each day strip has a continuous colored background computed from a gravitational field. Fixed events are segment masses; volatile items are point masses. Their fields overlap and blend, producing a color gradient that reflects the weight and distribution of your schedule.

Where no events are present, evenly distributed ghost masses maintain a neutral tint. The transition between colored and neutral is smooth — no thresholds or hard edges.

Four parameters control the rendering (accessible via the **Gradients** panel):

| Parameter | Slider label | Effect |
|-----------|-------------|--------|
| `peak_amp` | Intensity | Color vividness at event peaks |
| `decay` | Range | How far field influence spreads laterally |
| `ghost_pull` | Ghost pull | Weight of the neutral background field |
| `overlay_alpha` | Blocks | Opacity of the solid event block fill |

### Facets and colors

Facets represent life areas or agent domains. Each facet has a CI color defined in `agenda.json`. The legend at the top of the calendar is built from the `facets` array; click a facet to mute or unmute it.

The calendar renders in light mode only. No grey — the palette uses the six outheis brand colors.

## Time axis

The time axis is **non-linear**: each day is divided into six 4-hour segments, each with an independent visual weight. A higher weight gives that time range more screen space — more pixels per hour — making events easier to read.

```json
"time_axis": [
  { "from": "05:00", "to": "09:00", "weight": 0.5 },
  { "from": "09:00", "to": "13:00", "weight": 2.2 },
  { "from": "13:00", "to": "17:00", "weight": 1.8 },
  { "from": "17:00", "to": "21:00", "weight": 1.0 },
  { "from": "21:00", "to": "01:00", "weight": 0.5 },
  { "from": "01:00", "to": "05:00", "weight": 0.3 }
]
```

If `time_axis` is omitted, the calendar falls back to a linear 24-hour distribution.

The **day start** (`day_start`) defines the first visible hour. Default: 5 (05:00). All segment boundaries shift automatically when day start changes.

### Spread panel

Click **Spread** in the top bar to open the time axis configuration panel:

- **Tag ab** — sets `day_start` (whole hours only); all segment boundaries update automatically
- **Six segment rows** — each shows its `from–to` range and a weight slider (0.1–5.0)

Changes apply immediately to the visible layout and are saved with the next Save.

## Interaction

### Top bar

| Control | Function |
|---------|----------|
| ↻ | Reload `agenda.json` from disk |
| 7 / 14 / 30 | Set visible day range |
| Add item | Open create popup |
| Save | Write current state to `agenda.json` |
| Colors | Cycle facet color assignments (CI palette permutations) |
| Gradients | Open gravitational field parameter panel |
| Spread | Open time axis configuration panel |

### Drag and resize (fixed events)

- **Drag**: click and hold anywhere on the block, drag left/right. Cross-day drops are supported — the block moves to the target day strip.
- **Resize**: grab the left or right handle (appears on hover or when the block is unlocked). The block edge follows the cursor; the time label updates live.
- **× button**: demote the event to volatile (appears on hover). Requires confirmation.

### Drag (volatile items)

Click and hold a volatile label, drag to any position within the current day strip or to a different day strip. Position is saved to `agenda.json` on the next Save.

### Promote volatile → fixed

Open the edit popup (double-click) and add start/end times. The item is promoted to a fixed event.

## Edit popup

Double-click any item to open the edit popup.

| Field | Description |
|-------|-------------|
| Title | 3-row textarea — supports multi-line titles |
| Start / End | Time inputs (HH:MM) |
| Date / End date | Date inputs; two dates produce a multi-day event |
| × (time) | Clear time fields (promotes to volatile) |
| × (end date) | Clear end date |
| Facet | Select from available facets |
| Size | S / M / L — visual weight for volatile items |
| Tags | Raw tag input — structural tags are rebuilt on save |
| follows | Comma-separated titles of items this item waits for |
| precedes | Comma-separated titles of items this item blocks |

**Buttons:**

- **Save** — apply changes, auto-save
- **Done ✓** — reveals an optional comment field; confirm marks the item done with today's date and saves
- **Cancel** — discard changes
- **Delete** — remove item after confirmation

---

## Add item popup

Click **Add item** in the top bar. Fields: Title, Start, End, Date, End date, Facet, Size, Tags. The item is added immediately and saved.

## Dependencies

Items can declare ordering relationships with other items.

| Field | Direction | Meaning |
|-------|-----------|---------|
| `follows` | this item → predecessors | "I wait for these items to complete before I start" |
| `precedes` | this item → successors | "I block these items — they cannot start until I am done" |
| `relates` | associative | "I am connected to these items" — no ordering |

Both `follows` and `precedes` are independent primitives that express the same relationship from opposite perspectives. Use whichever fits the planning direction: go to the blocked item and add `follows`, or go to the blocking item and add `precedes`.

### effectiveDay

When a predecessor is not yet done, the calendar pushes the dependent item's display day forward:

```
effectiveDay(item) = max(effectiveDay(predecessor) + 1, item.day)
```

This is computed recursively with cycle detection. Done predecessors (`done` field set) no longer block.

**Deferred items** — pushed beyond their planned day — show a teal left border (fixed events) or a dotted underline (volatile items). The planned day stored in `agenda.json` is not modified; the shift is computed at render time.

To set a dependency: open the edit popup → enter the target item's exact title in "wartet auf" or "blockiert" → Save. Multiple items are comma-separated.

## Save and sync

| Trigger | Behavior |
|---------|----------|
| Save button | Writes current state to `agenda.json` immediately |
| Auto-save | Saves automatically every 60 seconds while there are unsaved changes |
| Tab hidden | Saves when the browser tab loses focus |
| Server merge | On save, server items not in the current view are preserved |

The Save button label shows **✓** when the current state matches disk. Any edit sets it back to **Save**.

Server-side items (added by cato or via CLI between page loads) are read back on Save and merged into the output — they are not overwritten. Recurring items are identified by their `#recurring-*` tag and preserved as single anchor items.

---

## Range

The **7 / 14 / 30** buttons in the top bar set the visible day range. Today is always the first row. The selected range is saved to `agenda.json` and restored on the next load.
